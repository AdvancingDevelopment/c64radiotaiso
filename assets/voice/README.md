# Voice samples — `assets/voice/`

Radio Taiso 64 speaks the counts (いち … はち), the two titles, 吸って / 吐いて
and お疲れさまでした as 4-bit samples played through the SID master volume
register at 5000 Hz (`src/digi.asm`, CIA2 timer NMI). The sample data is
generated by `tools/digi.py` into `src/gen_digi.asm` (4608 bytes staged at
$E000) and `src/gen_digi2.asm` (word tables + the rest, ≤ 6 KB of the data
segment). F5 toggles the voice while exercising.

## Regenerating

    python3 tools/digi.py            # deterministic; prints word -> bytes

Needs macOS `say` (voice *Kyoko*, ja_JP — check with `say -v '?'`) and
`ffmpeg`, Python 3 standard library only. The `say` renderings are cached in
`build/voice/*.aiff`; `build/voice/preview.wav` is the 4-bit result rendered
at 22050 Hz so you can listen to what the C64 will say. `build/voice/words.json`
holds the per-word metadata used by the tests.

Useful options (see `--help`): `--rate` (sample rate, default 5000),
`--preemph 0.5` (treble lift before quantising), `--drive 2.0` (soft-clip
compression, 1 = off), `--max-gap 0.08` (longest internal pause kept, s),
`--say-rate` (speaking rate for every word), `--top-half` (3-bit samples in
volume levels 8..15 so the music never ducks completely, at the cost of
resolution), `--no-split-title` (store ラジオ体操第一 / 第二 as two whole
phrases instead of sharing ラジオ体操 + 第一 / 第二).

Each count must be at most 0.42 s after trimming (one beat at 120 % tempo);
the tool refuses otherwise. If the words do not fit the budget it drops them
in this order: お疲れさまでした, then 吐いて / 吸って — the counts and titles
are mandatory.

## Recording your own voice

Drop a file named `assets/voice/<name>.wav` and it replaces the synthetic
word the next time you run `python3 tools/digi.py` (the report column
`source` then says `recorded`). Names:

| file | word | | file | word |
|---|---|---|---|---|
| `ichi.wav` | いち | | `radiotaiso.wav` | ラジオ体操 |
| `ni.wav` | に | | `daiichi.wav` | 第一 |
| `san.wav` | さん | | `daini.wav` | 第二 |
| `shi.wav` | し | | `sutte.wav` | 吸って |
| `go.wav` | ご | | `haite.wav` | 吐いて |
| `roku.wav` | ろく | | `otsukare.wav` | お疲れさまでした |
| `shichi.wav` | しち | | `title1.wav` / `title2.wav` | whole titles, only with `--no-split-title` |
| `hachi.wav` | はち | | | |

With QuickTime Player: *File → New Audio Recording*, record one word per
take in a quiet room, speaking briskly and close to the microphone (the
counts have to be short — 0.2–0.35 s is what the synthetic ones are), then
*File → Save*. QuickTime writes `.m4a`; convert it to WAV with

    ffmpeg -i ~/Desktop/ichi.m4a -ac 1 -ar 22050 assets/voice/ichi.wav

Any sample rate or bit depth is fine (ffmpeg resamples to 5000 Hz); leading
and trailing silence is trimmed automatically, internal pauses longer than
80 ms are shortened, the level is normalised. Avoid clipping and background
noise — at 4 bits, noise turns into audible gravel. Run the generator, listen
to `build/voice/preview.wav`, and check the printed byte budget.

## SID models and loudness

Volume-register samples rely on the DC offset of the 6581's master volume
DAC; the 8580 (C64C, C128) hardly has that offset, so on an 8580 the voice is
about 16 dB quieter — barely audible under the music — unless the machine
has the well-known "digi boost" resistor mod. VICE emulates both: the SID
model is under *Settings → SID → SID model*, or on the command line
`-sidmodel 0` (6581), `-sidmodel 1` (8580), `-sidmodel 2` (8580 + digi boost)
(`-sidenginemodel 256/257/258` selects the same with reSID). Measured peak
levels of the spoken words in a VICE capture of this build (music muted):

| SID | word peak |
|---|---|
| 6581 | −16 dBFS |
| 8580 | −32 dBFS |
| 8580 + digi boost | −14 dBFS |

## Verifying a build

    acme -DTEST_PLAY=1 -DTEST_DIGI=1 --format cbm --outfile build/d.prg src/main.asm
    # exact register-level check (silent, fast): every $d418 write vs the data
    x64sc -default +confirmonexit -sound -sounddev dump -soundarg build/d.dump \
          -autostartprgmode 1 -limitcycles 24000000 build/d.prg
    python3 tools/digi.py --check-dump build/d.dump          # add -ntsc to x64sc for NTSC
    # audio capture (real time, audible on the Mac; VICE's dummy device records nothing)
    x64sc -default +confirmonexit -sound -sounddev coreaudio -soundrecdev wav \
          -soundrecarg build/d.wav -soundrate 44100 -sidmodel 0 \
          -autostartprgmode 1 -limitcycles 30000000 build/d.prg
    python3 tools/digi.py --check-wav build/d.wav

The TEST_DIGI build speaks the 13 words once, one every 64 frames, ignoring
the play state's own requests; `--check-dump` verifies every nibble, the
chaining of the titles, the `$d418` restore after each word and the timer
period (the write times jitter by a badline, the mean is exact);
`--check-wav` verifies onsets, durations, silence between words, an
envelope match against the source data, and reports peak levels and
clipping. Exit code 1 at the cycle limit is normal for x64sc.
